# Mac 安装、构建与 GitHub 发布

## 源码直接运行

```bash
bash install_macos.command
bash launch_macos.command
```

首次运行会引导选择 JPG 输出文件夹。用户操作界面为中文。

## 本机打包 .app

```bash
bash build_macos.command
```

输出路径为 `dist/镜头切片.app`，已通过 PyInstaller `--icon assets/app_icon.icns` 写入新的黑白手绘场记板图标。若 Finder 仍显示旧图标，先确认使用的是新生成的 `.app`，并将旧版应用替换。打包时只生成本机架构应用，不承诺跨 Intel / Apple Silicon 通用。

## 在 GitHub Actions 上构建

在仓库上方进入 **Actions → 构建 Mac 应用 → Run workflow**（也会在推送到 main 时自动触发）。完成后在工作流页面的 **Artifacts** 下载 `scene-cutter-mac`。

目前工作流产出的是 **ad-hoc 签名但未进行 Apple Developer 公证** 的 `.app` 压缩包；跨电脑安装仍可能需要正式签名和公证。请自行确认 macOS Gatekeeper 的提示，勿将未签名包宣称为已公证的正式安装包。

## 已确认 GitHub 目标仓库

源代码的正式仓库地址为：<https://github.com/raynacocobobobo-arch/Scene-Cutter>。

`publish_github.command` 指向上述仓库，而**不是**过去计划中的 `SceneCutter-Mac`。该脚本仅可在空仓库时首次推送；远端已有提交时会停止以避免覆盖。可在 Mac 上执行 `bash publish_github.command`；如已从 ChatGPT 将文件推送到该仓库，则不需要再执行发布脚本。

## 3.4.1 打包兼容性修复

- Finder 中的应用显示名称仍为「镜头切片」，`CFBundleIdentifier` 固定为 `com.scenecutter.app`。
- 本机和 GitHub 构建均在打包完成后由 `/usr/libexec/PlistBuddy` 验证 Bundle ID，再使用 `codesign` 进行 ad-hoc 签名和验证。
- 每次打包前执行 `bash generate_macos_icon.command`，根据 `assets/app_icon.png` 重新生成 `.icns`。
- 旧版 .app 不会自动更新，请用新构建产物替换。
